# Demo UX goals

The current demo should make the backend loop easy to see.

The goal is not to impress people with visuals yet.

The goal is to make the proof obvious.

## Main demo message

> Actions go in, state comes out, and the log can explain what happened later.

## What the demo should show

The demo should show:

- backend starts or is detected
- happy path runs cleanly
- warning/error path catches ignored cues
- logs are written
- replay verification passes
- review summaries are readable
- chair, door, and smoke/visibility cue state are visible in the review
- security boundaries exist at the client/backend edge

## What Dr. Cameron should be able to notice

Dr. Cameron should be able to notice:

- the project has a clear foundation
- the scope is controlled
- the demo is repeatable
- the review output is understandable
- future Unreal/asset/physics work has a reasonable path
- the project is not claiming medical or operational authority

## Demo success criteria

The demo succeeds if someone can say:

1. I understand what the system is proving.
2. I understand what it is not proving yet.
3. I can see why the backend comes before Unreal.
4. I can see how replay and review support training.
5. I can see the next step.
